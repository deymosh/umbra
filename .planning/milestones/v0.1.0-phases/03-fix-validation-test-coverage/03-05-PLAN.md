Set up: define a second file-private web-socket double whose `close` first counts down an `entered` `CountDownLatch`, then blocks on a `release` `CountDownLatch` until the test lets it go, and then throws a marker exception so the dial aborts before reaching the connectivity probe or the transport call — the test must never attempt a real dial. Wrap the whole body in `try { ... } finally { TorProxyConfig.reset() }` and, at the start, call `TorProxyConfig.update("127.0.0.1", 9050)` so the readiness check passes and the dial reaches the socket-close step. Race: start a real thread that calls the client's dial method for that url. Release the `release` latch, join the thread with a bounded timeout, and assert the client's in-flight set no longer contains the url — proving the guard is released even though the dial ended in failure.

Keep using `wss://relay.invalid`: that top-level domain is reserved and cannot resolve, so even an unexpected code path cannot open a real connection.
