<objective>
Make `app/build.gradle.kts`'s `versionName` the single source of truth for the version Umbra
reports to the user, and retire the hand-maintained string resource that had already drifted
away from it.

Purpose: this is the phase tracer — the one change in Phase 4 that crosses every layer the
phase touches (Gradle build config → AGP code generation → Compose UI → Android resources)
and is fully verifiable end to end. Proving it first means the rest of the phase (changelog,
release verification, tag, skill) all describe a tree whose version story is already correct.
It also closes the concrete bug that motivated VERS-01/VERS-02: the app has been telling users
one version while the build produced another.

Output: `buildConfig = true` enabled, `SettingsScreen.kt` reading `BuildConfig.VERSION_NAME`,
and the redundant version string resource deleted.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gradle build config → generated `BuildConfig` class → shipped APK | Anything declared as a generated build field is compiled into the distributed APK in cleartext and is trivially readable by anyone who unzips it. Enabling the feature widens what *could* be put there, which is the only new surface this plan opens. |
| App UI → end user | The version string is a factual claim the app makes to the user about what they are running. |

Not applicable in this plan, stated explicitly rather than omitted: there is no network
boundary (no TOR/relay code touched), no signing boundary (no Amber path touched), no
persistence boundary (no Room/SQLCipher code touched), and no untrusted external input — the
one value flowing through this change is a compile-time constant baked in by the build.
