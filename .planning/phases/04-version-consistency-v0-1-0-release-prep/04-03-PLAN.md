<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local git refs → remote → release workflow → public artifact | A pushed tag matching the release pattern is the single trigger that builds, signs, and publishes a public release. Crossing this boundary is irreversible in the way that matters: the artifact is downloadable the moment it exists. |
| Written runbook → future maintainer's actions | A runbook is executed, not merely read. Anything it presents as a step will eventually be run literally, including by someone with less context than its author. Its text is therefore a control surface, not documentation. |
| Repository secrets → CI signing → published APK | The runbook describes the signing path; describing it badly is the realistic route by which a repo-local keystore gets introduced. |

## Reversibility note — why no checkpoint is inserted

The tag task carries a `one-way` reversibility rating for the record, because the door it stands
next to is genuinely one-way: a pushed release tag publishes a signed public artifact that cannot
be cleanly withdrawn. No `checkpoint:decision` precedes it, and this is deliberate rather than an
omission. The human has already made this decision and it is locked at the project level and again
in this phase's context — prepare the tag locally, leave the push to an explicit later go-ahead.
Inserting a checkpoint would re-ask a question already answered, which is the checkpoint-fatigue
anti-pattern. More decisively, no task in this plan performs the one-way action at all: the push is
categorically out of scope, so there is no door for the executor to walk through and nothing for a
gate to stand in front of. The plan therefore stays `autonomous: true`.
</threat_model>
